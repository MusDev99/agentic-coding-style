Foundations

🧭 Principles

Seven rules I apply to every agent-assisted change.

PrincipleIn practiceWhy
📝 Spec firstWrite the goal, constraints and done-criteria before the first prompt.Agents amplify ambiguity.
📦 Small diffsOne concern per branch. Under ~400 changed lines.Reviewable output is trustworthy output.
🧪 Verify, never trustTypecheck, tests and a real run before "done".Fluent code can still be wrong.
🔒 Least privilegeRead-only by default. Writes and deletes need explicit approval.Limits blast radius.
📚 Context is codeRules live in CLAUDE.md, checked into the repo.Every session starts with the same contract.
🔍 Ground in sourcesRetrieve docs and code before generating. Cite them.Cuts hallucination.
🧾 Docs ship with codeREADME and changelog update in the same change.Docs never drift.
Workflow

🔁 The working loop

Every task, from a one-line fix to a new service, runs the same five steps.

🗺️PlanGoal, files, risks. Human approves.
→
🧲GatherRead code, docs, schema. Retrieve, don't guess.
→
⚙️ActSmallest change on a feature branch.
→
🧪VerifyTypes, tests, build, run it.
→
📝RecordChangelog, README, PR notes.

When Verify fails, the loop goes back to Gather with the error attached. It never skips ahead. After three failed rounds I stop and rethink the plan.

Context engineering

📜 Context is the contract

A short, specific CLAUDE.md beats a long prompt. It carries the rules an agent cannot infer from the code.

Put inLeave out
Commands: dev, build, typecheck, testThings the code already says clearly
Data rules: source of truth, id formats, validation locationLong tutorials
Conventions: branch names, commit prefixes, UI lawsSecrets and credentials, ever
Definition of doneAnything that changes weekly
 
# CLAUDE.md (excerpt style)
- Validate on the server. Client validation is only for UX.
- All data access goes through one module. Never call the API elsewhere.
- Never hardcode config. It comes from the sheet / settings tab.
- Done = typecheck + build pass, verified in browser, README updated.

# Python: planner → parallel workers → critic (framework-agnostic)
async def run(task: Task) -> Result:
    plan   = await planner(task)                      # structured output, schema-checked
    steps  = [s for s in plan.steps if s.independent]
    parts  = await asyncio.gather(*(worker(s) for s in steps), return_exceptions=True)
    draft  = merge(plan, parts)
    verdict = await critic(draft, spec=task.spec)       # pass / fail + reasons
    if not verdict.ok and task.retries < 2:
        return await run(task.with_feedback(verdict.reasons))
    return Result(draft, verdict)

Narrow tools

Each worker gets only the tools its step needs. A search worker cannot write files.

Budgets everywhere

Max steps, max tokens, max wall time, max retries. Every loop has an exit.

Fix the question before you fix the model.

BigQuery

Partition by date, cluster by filter columns, select only needed columns, and check bytes scanned before running.

Fewer round trips

Batch reads and writes. One batch call beats N single calls, for Sheets, SQL and LLM tools alike.

Pipelines

🚰 Pipelines that survive retries

Agents fail in the middle. Design every stage so a rerun is safe.

📥TriggerSchedule or event.
→
📨QueuePub/Sub with a dead-letter topic.
→
🏭Stage workersIdempotent, typed in/out.
→
🧪Eval gateBlock bad output.
→
🚀PublishVersioned, reversible.
RuleHow
♻️ IdempotentDeterministic ids, such as {userId}_{date}, so upserts cannot duplicate.
📐 Typed contractsValidate every stage boundary with a schema (Pydantic, Zod).
🔁 Retry with backoffTransient errors retry. Permanent errors go to the dead-letter queue.
🔢 Order writesDelete children before parents so a failure never leaves dangling references.
👀 ObservableTrace id per run, per-stage latency, tokens and cost.
↩️ ReversibleVersion prompts, indexes and models. Keep a rollback path.
Guardrails

🛡️ Guardrails in layers

No single check is enough. Each layer catches what the previous one missed.

🚪
Input

Schema validation, length limits, PII masking, injection screening. Trim and normalize, then validate strictly.

📚
Retrieval

Treat retrieved text as data, never as instructions. Filter by the caller's permissions before search.

🧰
Tools

Allow-list per agent. Read-only by default. Confirmation for deletes, payments and sends. Dry run first.

📤
Output

Structured output checked against a schema. Citation required. Redact secrets and personal data.

🙆
Human gate

A person approves irreversible or customer-facing actions. The prompt says exactly what will change.

📟
Runtime

Rate limits, spend caps, timeouts, kill switch, audit log.

Threats and answers

ThreatDefense
Prompt injection in documentsSeparate data from instructions. Strip tool-call syntax. Never let retrieved text widen permissions.
Hallucinated factsGrounded answers with citations. "Not found" is an allowed answer.
Leaked secretsNever read or print .env or key files. Secret scan before every commit.
Runaway loops and costStep, token and time budgets. Alert on spend.
Destructive actionsLeast privilege, confirm dialog, backup before bulk change.
Unauthenticated admin endpointsAdd an auth guard before any public deploy.
 
# Python: validate model output before acting on it
class Action(BaseModel):
    tool: Literal["search", "update_row"]
    args: dict
    reason: str

def guarded(raw: str, user: User) -> Action:
    act = Action.model_validate_json(raw)               # schema
    if act.tool not in user.allowed_tools: raise Denied(act.tool)   # permission
    if act.tool == "update_row" and not user.confirmed: raise NeedsApproval(act)
    return act
Evaluation

📏 Evals before opinions

I keep a small golden set from real questions and run it on every prompt, model or index change.

LayerMetricQuestion it answers
🎯 RetrievalRecall@k, MRRDid the right chunk come back?
✍️ GenerationFaithfulness, answer relevanceIs it supported by the chunks?
🤖 AgentTask success, steps, tool errorsDid it finish the job efficiently?
⏱️ Systemp95 latency, cost per taskCan we afford it at scale?
🛡️ SafetyInjection pass rate, refusal accuracyDo the guardrails hold?

Automated checks run first, then an LLM judge with a written rubric, then a human spot-check on a sample. A change ships only if the golden set does not regress.

Roadmap

🗺️ Roadmap to a mature agentic practice

Four phases. Move on only when the exit check passes.

Phase 1 · Weeks 1–2

🧱 Foundation

  • Rules file per repo
  • Branch and commit conventions
  • Typecheck and test gates

Exit: every PR passes gates

Phase 2 · Weeks 3–6

📚 Grounding

  • RAG over docs and runbooks
  • Hybrid retrieval and rerank
  • Golden eval set

Exit: recall@5 target met

Phase 3 · Weeks 7–10

🎛️ Orchestration

  • Router and parallel workers
  • Critic step on risky changes
  • Tracing and cost dashboards

Exit: task success tracked

Phase 4 · Ongoing

🛡️ Hardening

  • Injection tests in CI
  • Auth on admin surfaces
  • Quarterly eval refresh

Exit: no unreviewed side effects
